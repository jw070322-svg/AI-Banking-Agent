# 第二阶段：审核知识与审计完整性（1030）

## 新增完成
- 审计链与金融账本共用SQLite事务：审计校验或写入失败时，业务写入一起回滚。检测历史内容修改、记录缺失和链不一致。
- 新增只读审计核验工具，并能生成单独保管的检查点；用旧检查点检测整段尾部删除。没有外部检查点时，不宣称能检测管理员重写全库或成段回滚，也不是WORM审计。
- 可显式以 --review-db 启用已审核知识版本；每次问答建立不可变检索快照，只使用该版本选中的已有原文。发布或回滚下次问答生效；原文变化/无发布版本则拒答，不回退到未审核知识、固定词典或外部搜索。
- 本轮没有代替人工批准任何实际知识。测试只在临时目录制作审核样例；线上默认仍为原知识模式。
- 身份权限伪造检查扩展到嵌套参数；接入原工具层的有界JSON检查，拒绝过大/过深输入。

## 实际验证
53项新增及集成后端检查、8项前端检查通过。105道题重新离线运行，引用结构校验无误、账本未变，答案仍需人工业务评分。原690文件哈希未变。浏览器截图为上一轮既有布局证据，本轮新增能力以真实HTTP及临时数据库测试验证，没有冒充新截图。

## 操作方式
普通预览：python3 start_review.py --port 8802
启用本地已审核版本：python3 start_review.py --port 8802 --review-db /绝对路径/审核库.sqlite3
审核库由 python3 -m review_additions.releases 管理。审核者是本地标识，不能冒充真实银行员工认证。
只读审计核验：python3 -m review_additions.check_audit --db /绝对路径/账本.sqlite3
留存检查点：在上面加 --save-checkpoint /另行保管/检查点.json
核对检查点：在上面加 --checkpoint /另行保管/检查点.json
检查点不会覆盖已有文件；需要在权限隔离的地方保管才有外部锚点意义。
