# UI与旧缓存报错诊断报告
日期：2026-10-30。版本：AI_Banking_Agent_1030.ver2。

## 检验事实与原因
### UI遮挡
1030.ver1仍以fixed定位摘要按钮，只修改bottom距离。宽屏左侧摘要会与侧栏“授权与控制”重叠，窄屏又与服务入口及理财底栏竞争空间。单独调整偏移无法处理不同屏宽、文字换行与页面内容。
本版新增正常文档流中的“服务工具”栏，四个原按钮保留原节点及事件，窄屏两列排列。工具栏不覆盖侧栏或底部对比栏，也不会复制按钮。

联调发现：把工具栏放进bank-app内部，会让原journey-workspace.js第190行的网络禁用/恢复逻辑与planning-market.js的launchState共同管理同一组按钮；前者可能保存到已经被后者设为disabled的值，导致请求结束后仍禁用。
最终工具栏位于bank-app外的正常文档流，按main侧栏距离对齐。保留原按钮状态管理，不强制解除业务禁用状态。

### 缺失缓存
1. 复现入口：tests/test_tools_security_1029.py第375行test_preservation。第379至380行无条件读取incoming清单的每一个文件，首次在__init__.cpython-314(2).pyc上抛出FileNotFoundError。
2. reports/1029-preservation-baseline.json包含618个原基线文件和73个输入，其中32个为历史pyc。缺失的不是32个业务源码模块。
3. 实测时间线：1029.ver1仍有全部32个旧缓存；1029.ver2、1029_rag_review、1030.ver1均无这些文件。因此首次缺失定位到1029.ver1→1029.ver2交付边界，不能归因于本轮UI修复。未找到该次拷贝命令的完整证据，不能断言当时具体哪条命令删除了它们。
4. 原Teammate_output/eva output/1029仍保留这些缓存。本轮只核对哈希，不执行旧字节码。
5. 工具源码位于tool_calling/tools；历史缓存为平铺命名，不可简单按缓存目录推断运行模块路径。本轮按源码清单映射，并核对每个实际模块的__file__来自.py。
6. 659个非缓存必需文件全部存在且哈希一致；诊断前后项目pyc数量均为0。使用python -X utf8 -B运行，子进程也禁写缓存。

## 诊断结论与处理
缓存报错属于交付清单和保全检查没有区分源码与可再生成缓存的问题。在本轮无缓存运行、源码校验及266项后端功能/整链测试范围内，没有发现缓存缺失导致的模块无法加载、账本运行故障或安全边界失效。
这不等于证明整个系统没有漏洞，也不替代真实银行服务与生产认证验收。

保留旧清单与旧失败证据，不补造pyc、不删除旧测试、不将其标记为通过。新增诊断把“运行健康”和“历史交付物完整性”分开呈现：运行健康通过，历史缓存保全仍不通过。
后续发布应以.py、配置、知识数据及正式资源作为运行必需清单；旧缓存若要留档，应放来源归档中，而不应成为运行门槛。
正常用户启动无需找回这些旧缓存。

## 使用与复验
双击“启动1030_UI修复版.bat”，访问 http://127.0.0.1:8804/ 。
本版旧启动器保持原样，使用旧启动器不会加载本轮UI补丁。
复验：python -X utf8 -B -m ui_fix.diagnose
Windows隔离环境可能阻止临时数据库或回环端口；遇到权限错误应在正常本机权限下复验，不应归类为缓存故障。本轮已如此完成。
默认使用独立演示数据库runtime/ui-fixed.sqlite3；没有复制用户运行库或调用付费API。
审核知识模式仍可加--review-db，沿用上一版的审核范围保护。
