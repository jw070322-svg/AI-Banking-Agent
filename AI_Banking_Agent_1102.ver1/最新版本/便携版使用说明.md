# AI Banking Agent 1102.ver1

## 在另一台电脑启动

1. 准备 Windows x64、Python 3.11 或更新版本、Node.js 18 或更新版本。用 `python --version` 和 `node --version` 确认两条命令都可用。推理使用 CPU。解压和运行时目录需要可写。
2. 收到成品 ZIP 后，用 PowerShell 执行 `Get-FileHash .\AI_Banking_Agent_1102.ver1.zip -Algorithm SHA256`，与同名 `.zip.sha256` 核对。完整解压，保留所有子目录。
3. 双击 **启动最新安全自评版.bat**，看到“本地模型已就绪”和网页地址后，保留窗口，打开 http://127.0.0.1:8808/ 。模型只在 127.0.0.1:8811 监听。可从网页的知识问答发起通用问题。
4. 在同一份解压目录执行 `python -X utf8 -B tools/verify_portable_inference.py`。它检查密钥、已挂载的适配器、一次真实生成和网页知识问答。看到 `web_model_received` 为 true 且 `external_data_sent` 为 false 即通过该项测试。

## 从 Git 仓库取得同一版

有该私有仓库的读取权限并安装 Git LFS 后，在 PowerShell 执行以下命令。大模型权重使用 LFS 存储。

```powershell
git lfs install
git clone --branch codex/1101-portable-local-model --single-branch https://github.com/jw070322-svg/AI-Banking-Agent.git
cd AI-Banking-Agent
git lfs pull
cd AI_Banking_Agent_1102.ver1/最新版本
```

直接分发时选用本项目生成的成品 ZIP。GitHub 网页上的源码 ZIP 是否含完整 LFS 权重取决于仓库配置。小文本指针无法启动模型，启动器会报告对应文件校验失败。

## 模型文件与启动链

| 组件 | 项目内位置 | 用途 |
| --- | --- | --- |
| Qwen2.5-0.5B-Instruct Q4_K_M | `model-assets/qwen2.5-0.5b-instruct-q4_k_m.gguf` | 基础权重，491,400,032 字节 |
| 金融 LoRA | `training/lora-finance-qwen05b-full/adapter-qwen2.gguf` | 启动时挂载，模型别名 banking-finance-lora |
| llama.cpp b11900 | `model-assets/llama-b11900/` | Windows x64 推理服务和 CPU 动态库 |
| 完整性与许可 | `model-assets/manifest.json`、同目录的 LICENSE 文件及运行库内的 OpenMP 许可 | 固定来源、逐件大小与 SHA-256 |

8808 启动器调用本地引导程序。冷启动校验权重、LoRA 和推理二进制，然后在当前版本的 runtime 目录生成随机密钥。服务启动后检查模型别名、活动 LoRA 和错误凭据拒绝结果，再开放网页。通用知识问答优先查本地词库和 RAG；缺少证据时才会用模型辅助。未经核实的模型回答不会成为引用或交易依据。模型推理可离线运行，网页的公开行情和经同意的官网核验仍需要网络。随包推理程序面向 Windows x64。

## 重新打包和排障

- 在版本根目录执行 `python -X utf8 -B -m security_integration.package`。脚本检查历史交付哈希与模型清单，在上一级生成 ZIP 和 SHA-256 文件。权重、适配器、动态库、源码、测试与技术报告一起归档。每份解压副本首次启动时创建自己的密钥和模拟账本。
- 启动失败时运行 `python -X utf8 -B tools/diagnose_local_model.py`，结合 `runtime/local-ai-status.json`、`runtime/launcher.stderr.log`、`runtime/llama-server.stderr.log` 定位问题。校验失败时重新完整解压或执行 `git lfs pull`。
- 同时运行两个副本会争用端口。用 `netstat -ano | findstr :8811` 找到监听 PID，通过任务管理器核对可执行文件路径后结束属于旧副本的 llama-server.exe，再启动所需副本。关闭网页服务窗口后，模型进程可以继续响应本副本的下一次启动。
- 安全自评使用 `python -X utf8 -B -m security_integration.self_assess`。便携模型的实际推理测试与安全回归分开执行，两类证据分别见技术报告。
