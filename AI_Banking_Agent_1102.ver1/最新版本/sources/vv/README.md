# Banking · 统一版

无框架依赖的本地沙箱。四个主导航与产品、持仓、订阅、资金计划、权限和任务共用一份状态。未连接真实银行、大模型、真实 MFA 或持久审计。所有数据和产品均为虚构。刷新重置。

## 启动

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

打开 http://localhost:4173/#/overview 。也可直接打开随附「Banking 统一版.html」。

## 信息架构
- 总览：统一总资产、可用资金、持仓、目标、收支、订阅和待办。
- 收支与订阅：月份/分类/关键词查询、账单详情、分析、周期扣费核实、保留或取消。
- 理财：产品与推荐、资金计划、我的持仓。风险/期限/流动性/起点筛选、匹配说明、2–3 项对比、预演、申购与赎回。
- 任务与记录：所有操作、状态筛选、失败重审、未知回执查询、到账查询、决策快照与依赖、任务中断/恢复。
- 授权中心与沙箱设置为全局入口；自然语言仅有限场景定位，金融条件不自动执行。

## 三条演示路径
1. 总览 → 分析账单 → 授权查询与订阅 → 分类分析 → 核实订阅 → 确认取消 → 查看回执。取消只减少未来支出，不退当期费用或增加余额。
2. 直接进入理财 → 修改资金目标/预算 → 筛选与对比至少两款 → 选择产品、调整金额与预演 → 授权交易 → 审阅并输入演示码 246810、勾选确认 → 模拟申购 → 持仓与总览同步更新。也可以保存保留流动性的方案。
3. 我的持仓 → 从期初无锁定持仓发起赎回 → 模拟验证并提交 → 待到账 → 沙箱设置推进 1 天 → 任务查询到账 → 余额与持仓同步变化。锁定期产品不允许提前赎回，测试到期需显式推进业务时钟。

## 测试分支
授权中心可拒绝或撤销各类权限。关闭确认会取消未执行操作。修改目标、产品、金额、预算、档案、授权或业务日期使旧确认失效。

沙箱设置选择新操作返回成功/失败/未知；未知结果冻结后续写入，只能查询原回执，不重发。赎回成功提交是 processing，直到次日模拟查询确认才到账；到账失败释放占用，保留持仓。连续 3 次执行失败或演示验证错误触发执行锁；核实后可重置锁，不清空账本。

## 数据边界
金额均为整数分。初始可用 ¥38,640、期初模拟持仓 ¥90,000，总资产 ¥128,640。所有申赎、失败、未知和取消分支保持总资产守恒，不计收益与费用。历史支出已包含订阅，取消不会改历史账单。

预演：当前已确认可用资金作为起点；用户设置未来收入/支出预算；已确认订阅节省下月计入；当前配置先扣可用资金，固定期样本假设到期主动赎回并在次月恢复本金，不是银行收益或到账预测。现有持仓不假设自动到账。模拟月固定 30 天。

## 代码与验证
- dist/index.html：唯一壳层，只加载统一版脚本和样式。
- dist/journey-engine.js：封装账本、权限、产品规则、版本、申赎状态与快照；外部读取为副本。
- dist/journey-workspace.js：四路由、页面、弹窗和事件；不加载旧版独立工作区。
- dist/journey-workspace.css：统一设计系统、1440 桌面与 390 窄屏布局。
- tests/core.cjs：15 组有意义规则检查；有 Node.js 时可运行 node tests/core.cjs。此环境使用 Node 运行时执行通过。
- tests/verified-results.json：本轮已通过规则清单。

浏览器验证：完整账单/订阅、比较/预演/申购、赎回/等待/到账三条路径；明确失败和重审、未知回执查询、无权限拦截、关闭确认、金额隐藏、自然语言定位、月份分类、产品风险期限和起点筛选、空状态与对比入口。1440×1000 和 390×844 均检查，未发现页面横向溢出；控制台未见应用错误。
