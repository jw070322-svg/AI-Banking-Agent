# AI Banking Agent 项目背景

## 1. 项目目标
我们正在构建一个 AI Banking Agent 项目，目标是让 AI 在银行场景中理解用户需求、分析金融问题、给出解释性建议，并在高风险场景中进行安全判断与人工确认。

本项目的重点不是“简单聊天”，而是：
- 理解用户的银行业务需求
- 检索金融知识与银行业务规则
- 区分正常情况和异常情况
- 提供带依据的回答
- 在越权、敏感或高风险场景中拒答或转人工

## 2. 项目定位
本项目属于 AI 金融助手 / AI Banking Assistant 的原型研究方向，适合在 FinTechathon 这种比赛场景中展示。

核心思路是：
- AI 负责理解需求、检索知识和生成建议
- 金融逻辑由确定性规则和清晰定义来支撑
- 风险和权限控制作为关键模块
- 评测题集用于证明系统的可信性和安全性

## 3. 业务场景
本项目优先围绕以下金融场景展开：
- 现金流分析
- 储蓄率分析
- 订阅扣款与重复扣款判断
- 退款问题
- 转账失败或到账延迟判断
- 金融行为解释与预算建议

## 4. 为什么不直接使用真实客户数据
本项目不使用真实客户姓名、账号、身份证、卡号、手机号、真实交易流水或个人隐私信息。

我们遵循的原则是：
- 不获取真实客户数据
- 只使用脱敏知识和典型业务场景
- 所有金融判断都依赖标准业务规则与知识库
- 对敏感信息、越权访问、未确认操作必须拒答或转人工

## 5. 当前阶段目标
当前阶段的重点是：
- 建立项目目录结构
- 整理银行业务知识
- 制作知识库文档
- 设计评测题集
- 准备演示素材和答辩说明

## 6. 项目模块说明
- Agent：负责理解需求和任务编排
- Knowledge Base：放置银行业务知识和规则
- RAG：从知识库中检索更符合场景的依据
- Evaluation：用于正常题、边界题和风险题测试
- Risk & Security：控制权限、判断风险、拒答越权请求
- Documentation：说明文档、评测记录和汇报材料

## 7. 项目亮点
本项目的价值主要体现在以下几点：
- 不是简单聊天机器人，而是围绕真实金融行为设计
- 强调可信性和解释性
- 展示了高风险场景下的拒答与人工确认机制
- 通过知识库和评测题集证明结果不是“胡编”

## 8. 后续计划
1. 完成银行业务知识库
2. 整理常见客户问题和异常场景
3. 建立最小 RAG 检索流程
4. 设计正常题、边界题和风险题
5. 整理展示材料和答辩说明
