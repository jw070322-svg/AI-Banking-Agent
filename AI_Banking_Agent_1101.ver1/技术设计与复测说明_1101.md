## 【修订】系统结构与安全控制

架构范围   |   网页业务、控制面与公开数据处理

网页业务调用链：HTTP 请求校验 → IntegratedService → WebGuardian（继承 HardenedToolGateway）→ 本会话权限、确认与风险证据 → LedgerGateway / 原业务引擎 → 工具输出检查 → 同一 SQLite 事务的提交、回执与审计。

| 环节 | 在 1101 包中的职责 |
| --- | --- |
| 请求与会话 | 仅允许本机监听。核对 Host、Origin 和演示会话。业务 POST 须为 application/json，不超过 64 KiB；拒绝重复键、NaN、重复 Content-Length 与 Transfer-Encoding。 |
| 授权与确认 | LedgerAuthorizationPort 从已加载的账本状态取得客户、会话和当前授权。资金、订阅、卡片与预算按业务范围检查；执行前核对操作 ID、参数、账本版本、期限与预览哈希。 |
| 风险和输出 | WebApprovalEvidenceBridge 将原网页批准绑定到本次风险证据。累计超过 1,000 元的模拟转账按既有规则核验绑定断言。缺少断言则拒绝。必要审计不可写或输出被阻断时，受测本地资金变更不提交。 |
| 日志与增强 | guardian_events、guardian_dispatch 保存事件及关联信息，会话标识为 SHA-256 摘要。开发者登录按会话 5 次/分钟、地址 20 次/分钟限速。响应附防嵌入头，健康及分析状态隐藏诊断目录。 |

### 覆盖范围

普通业务的新请求及知识研究调用经过 Guardian。研究联网时不占用账本写锁。独立 13 工具目录继续保留，网页执行使用原有业务数据与账本。

健康检查、会话建立、静态文件、安全状态以及操作摘要、开发者控制等有独立处理路径。公开行情在原业务返回后补入。命中已有幂等响应时还存在“复测发现与验收条件”所述的缓存例外。

## 【新增】复测发现与验收条件

缺陷记录   |   以同一会话、同一账本核对预期与实际

### G01   撤权后，旧请求键仍能读取账单摘要

在一个演示会话中开启读取权限，以固定幂等键 K 调用 /api/rpc 的 summary 方法，查询 2026-10 账单。成功后撤销读取权限。使用相同参数分别以新键和 K 重试。

| 条件 | 实测结果 |
| --- | --- |
| 新键 | 当前授权检查拒绝读取，返回 SCOPE_DENIED。 |
| 旧键 K | 仍返回先前成功响应，与原响应一致；调度计数前后均为 11。 |

原因定位：first_agent/service.py 的 _call_local 在重新调度前直接返回命中的缓存响应。实测影响是本会话可再次取得撤权前的摘要。本例未发现跨会话泄露或再次扣款。

修复验收条件：对缓存读取复核当前会话、资源归属、权限及期限。撤权后两种键都应拒绝返回旧内容；仍获授权的重复提交只能查询原回执。

### D01   报告生成器仍按打包前路径验收

生成器在检查 907 项历史输入时找不到三个原路径。用 package-manifest.json 独立核对，904 项在原址且哈希一致；旧启动器和旧说明两项已移入 history_version/launchers_before_1101，哈希一致；一个环境模拟器运行库按清单排除。未发现意外缺项或字节不符。

修复验收条件：生成器以发布清单映射核对原哈希，允许清单中明确排除的运行库。对篡改或未登记缺失继续报错，并能在全新解压目录生成标有本次测试时间的报告。
