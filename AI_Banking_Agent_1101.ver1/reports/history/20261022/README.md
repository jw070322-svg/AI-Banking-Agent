# AI Banking FirstAgent

本包把队友交付中的界面、模拟业务、安全组件和知识资料接成同一个本地服务。金额以整数分传输，SQLite 同一事务保存账本、幂等结果和审计。当前为规则驱动 Agent，无外部模型调用，全部银行、产品及验证均为模拟。

## 运行

需要 Python 3.11+、Node.js 18+，均只用标准库，无需安装 Python 或 npm 依赖。本次在 Python 3.14 与本机 Node 环境验证。

```powershell
cd F:\AI_Banking\FirstAgent
python -m first_agent.server --port 8765
```

打开 http://127.0.0.1:8765/ 。也可执行 `run_agent.ps1`。只能通过服务访问，不能直接双击 HTML。按 Ctrl+C 停止。业务数据保存在 `runtime/agent.sqlite3`，关闭服务后再次启动会恢复；浏览器会话 cookie 须保留。

## 演示路径

1. 打开右下角“Agent · 对话与转账”，点击“开启演示查询与交易权限”。用户拥有自己的虚构账户界面快照；此按钮单独授权 Agent 查询和执行工具。
2. 输入“分析账单并看看订阅扣费”，核对工具列表和聚合结果。在“收支与订阅”中查看单项订阅、核实后取消；未来支出下降不增加当前余额。
3. 输入“给张三转账”，系统要求补金额；回复“800 元”，核对预览后点击“核对后确认模拟转账”。当日累计超过 1000 元时使用明确标注的演示码 246810；它不是真实银行验证。
4. 刷新页面核对余额、账单，再在助手中点“查看转账记录”。关闭再启动服务仍可恢复。
5. 在“理财”中筛选、预演、申购或从期初持仓赎回。赎回先 processing，推进一个模拟日、查询成功后才增加可用资金。锁定期加次日结算必须在目标期限内。
6. 输入“什么是债务比率”，核对摘录、引用 ID、文档哈希及行号；未知问题返回 no_evidence，不执行业务工具。

期初可用 3,864,000 分、持仓 9,000,000 分，总额 12,864,000 分；这是 vv 的虚构账本快照。模拟业务日期继承源版本的 2026-10-19，与实际操作审计时间分别记录。浏览器验收会话已发生一次模拟 800 元转账；新浏览器会话独立初始化。

## 验证与协作

```powershell
python verify_delivery.py
```

验证会使用临时数据库，不写正常演示账本。Windows 受限沙箱可能需要允许本地端口和临时目录访问。报告见 `reports/verification.json`、`reports/integration-tests.txt` 和 `reports/vv-tests.json`。

`summary.md` / `summary.json` 是总版和各队伍交接；`context_log.md` / `context_log.json` 保存本次执行上下文及额度采样；`API-CONTRACT.md` 为统一接口。输入清单含原始路径、修改时间、SHA-256，补丁来源见 `reports/patch_manifest.json`。原始协作目录保持原样，`sources/` 保存选中交付的参考快照；不要把该快照直接当可运行包。

## 边界

身份是本机演示会话，无真实登录、MFA 或银行连接；模拟工具结果由演示设置指定。自然语言只支持已列出的规则和澄清，未接入开放式模型。订阅自动识别、定时/手机号/AA 转账、卡申请与挂失、生日商户联动没有在首版实现。原 eva 全套测试因原交付缺件不能直接运行，不能把本包测试结果记作其原版 42 项通过。审计与账本同事务持久化，但普通 SQLite 不是防篡改生产审计系统。

结论：这是可复跑、可核验、统一账本的首次集成 Agent；后续分支按总版契约继续接入。
