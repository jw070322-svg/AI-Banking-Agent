# 这版在做什么

这是在组长的1029.ver2基础上补安全自评：给助手出题、核对回答来源、记录操作过程，并检查记录会不会串用户、重复或泄露输入内容。

## 打开哪个文件

- Mac：运行 `启动安全评测续作版.command`。
- Windows：运行 `启动安全评测续作版.bat`。
- 或在本目录运行 `python3 start_review.py`（Windows可用 `py -3 start_review.py`）。

需要 Python 3.9以上、Node.js 18以上。默认网址是 `http://127.0.0.1:8802/`。保留启动窗口；关闭服务后网页无法读取后台。这个网址只在运行项目的电脑上有效。给组员交付请发整个压缩包，让对方解压启动。

旧启动文件保留原样；要使用这次的功能，必须使用带“安全评测续作版”的新入口。服务默认保存到 runtime/review.sqlite3。交付包不包含本次浏览器测试的账户数据库。

## 可以直接看到的变化

页面新增“操作摘要”入口。自愿开启后，可查看页面操作与服务结果、关闭记录、立即同步、标记需要核对或删除摘要。记录类型是可读中文，不显示JSON或测试指令。

助手收到明确的他人账户查询、绕过确认等要求会拒绝；询问个人产品适配和具体风险时，会要求核对业务资料。原文引用可在当前电脑打开。

只保存事件类型与处理状态；不采集输入框原文、密码、验证码或用户画像。可选摘要与必要的银行任务回执不同；删摘要不会改余额。已返回的服务请求只显示其结果，不把历史“开始处理”重复显示为待处理。

## 怎么查验收结果

打开 `reports/review-continuation/本轮安全自评说明.html` 看概览；`知识问答核对.html` 可逐题查看实际回答与原评分要求。

复跑新增规则及整合业务路径：`python3 run_review_checks.py new`。

复跑105道知识题：`python3 -m review_additions.evaluate`。默认离线评测，不调用外部模型或搜索，不把题目加进知识库。

复跑原项目检查：`python3 run_review_checks.py inherited`。原包有一项历史文件检查引用了未交付的32个Windows Python缓存文件，这项会报错；本轮另对压缩包实际提供的全部690个文件做哈希校验。不要把该报错隐藏，也不要补造缓存文件来伪造通过。

## 还不能说已经完成的事

- 105题的来源结构已经核对，但回答内容仍需按原评分表逐题人工评分。有真实来源不代表回答切题。
- 当前会话隔离不是银行身份认证；本地数据库也不是不可篡改的生产审计服务。
- 原项目另一套 tools/security 模块仍没有全面迁移到主网页调用链。本次不声称全站已经通过安全认证。
- 人工候选、审核、版本发布和回滚工具管理的是审核材料，不会自动把用户反馈变成线上知识，也不会自动训练模型。
- 本轮主要验证本地摘录式RAG和模拟业务。外部大模型、搜索、Google账号、真实银行、真实强身份验证均未做生产验收。
- 事件摘要覆盖已列出的页面交互与业务服务调用，不保证每个DOM变化、每次输入或强制关闭前的事件都留存。边界详见验收清单。

原始压缩包不变，解压得到的690个原文件也逐字节保留；新增模块通过新启动入口在HTTP响应中加载。没有改动原网页布局或原账本计算文件。
