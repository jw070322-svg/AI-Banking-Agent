# Banking 前后端整合版

这一版把最新前端接到压缩包中的本机模拟后台。保留现有布局、六个场景卡片、字体、自然语言入口和校园加载效果；不再另开旧助手工作区。

## 怎么打开

1. 解压整个文件夹。电脑需要 Python 3.9 或以上，以及 Node.js 18 或以上。无需另外安装 Python 第三方包。
2. Mac 双击「启动网页.command」；Windows 双击「启动网页.bat」。也可在文件夹内运行 `python3 start.py`（Windows 可用 `py -3 start.py`）。Mac 若系统不允许双击脚本，可用终端启动，不需要关闭系统安全保护。
3. 保持启动窗口开启，在浏览器打开 http://127.0.0.1:8793/ 。关闭窗口会停止服务，重新启动后记录仍在。

不要直接双击 web/index.html，也不要用以前的独立 HTML 文件测试整合效果。前后端必须通过上面的本机网址一起运行。其他电脑不能访问你的127.0.0.1；分享给组员请发送整个压缩包，由对方启动。

本机若已有 Codex 的 Node 运行环境，启动器会尝试使用；它没有打包进项目，其他电脑仍需安装 Node。端口被占用时可运行 `python3 start.py --port 8791`，再打开对应网址。

## 现在的数据在哪里

余额、账单、卡片、订阅、持仓、授权、任务统一由本机服务保存，默认数据库在 runtime/agent.sqlite3。刷新页面不会清空。浏览器只保存服务的显示快照，不维护第二套余额。原独立HTML的浏览器数据不会自动迁移；本交付包不附带测试数据库或组员原来的会话记录。

开发者工具的默认测试码仍为 **bnbu**，现在由本机服务核对。解锁后「一键重置全部信息」会恢复当前演示会话的初始卡片、余额、权限和任务；保留最近一次重置前备份，可在开发者工具中恢复。服务内部的审计事件不会被伪装成从未发生。刷新页面后需重新解锁测试工具。测试码不是正式用户登录系统。

## 已接通

- 最新页面中的模拟转账、卡片申请/额度/限制/解锁/挂失、订阅核实/取消、理财申购/赎回、授权和统一任务记录，使用后台同一账本。
- 自然语言模板仍支持姓名与金额变量；识别只引导核对，不代替交易确认。
- 助手的「分析现金流与预算」「什么是债务比率」连接原后台分析及知识检索，输出为客户可读的结果与引用，不展示原始JSON。
- 理财里的「查看账户分析推荐」读取后台分析推荐；结构化适配与执行仍经过确定性规则。
- 请求改为异步；实际请求时防重复提交。请求结果不明时先核对后台快照，不自动重复扣款。等待动画只是提交前体验，不冒充真实进度。

## 仍是模拟项目

没有接入真实银行、真实支付或真实身份验证。业务自然语言仍以规则识别为主；知识查询先检索本地资料，缺少依据时可连接百度和本地 llama.cpp，但无核验正文的模型解释不会展示。产品为虚构演示样本，不承诺收益。定时转账、AA收款、商户预订等未实现。SQLite记录是本机演示留痕，不等于生产级审计服务。当前模型缺少专用身份、服务鉴权及经验证的出站隔离，不能当作生产银行系统部署。

## 本轮修复：追问后自动填表

顶部助手输入“给小王转账”，页面显示收款人小王、金额待补充。接着回答“800元”“800块”或“800”，自动打开现有转账表单，填写收款人和金额。裸数字仅在当前金额追问中按人民币解释并提示核对；没有上下文时先询问收款人。

这一步只填写信息，不建立金融操作、不扣款。你可以在原表单改付款卡、收款人和金额，再点击生成确认，经过原有确认与必要的演示验证后执行。继续对话补充会保存当前表单条件；修改使关联的旧确认失效。取消只取消未执行步骤，不回滚已完成业务。

上下文由本机服务保存，关闭助手或刷新后可继续；切换到查询余额等新任务会结束未完成的填写流程。信息完整时可从助手恢复已填写表单。原始独立HTML没有更新，必须打开本整合项目的HTTP网址。

此前118项后端检查、66项前端检查通过。浏览器实测“给小王转账→800元”自动填表，以及关闭/刷新后“给林晓转账→800”填表、原确认页与关闭取消；见reports/fill-handoff-browser.json。业务仍为受限规则与模拟银行；预约、多笔、外币和复杂条件不执行。本地生成模型的最新能力与限制见本文开头。
