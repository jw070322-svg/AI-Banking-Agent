# Banking 前端模拟版交付说明

本轮基于本机独立前端实施，未获得或修改组长的 FirstAgent 服务端集成代码。保留四主导航、六场景卡片及现有字体/视觉设计。

## 使用

直接打开 `Banking 前端模拟完整版.html`。首页六场景区选择“打开模拟转账”或“管理模拟银行卡”。右上角授权中心开启对应权限，每笔敏感操作输入演示码 **246810** 并勾选确认。

所有联系人、银行卡、产品和金额均为虚构样本，不发送真实金融交易，不连接模型、小组后台或真实身份验证。

## 本轮完成

- 一个确定性模拟引擎管理余额、账单、订阅、持仓、转账、银行卡、授权和任务。
- 虚构名册转账：支持姓名/手机号/名册备注检索；选择付款借记卡、核对收款人与金额、确认及模拟验证；成功后余额/总资产/账单/任务同步。余额与累计日限额由规则层检查。
- 卡管理：申请、调额、限制/解锁、挂失；挂失不可直接解锁；申请先进入待审核，推进一个模拟日后查询，通过后才生成模拟卡；新借记卡可用于转账。
- 借记卡额度是单日转账限额，信用卡额度仅样本字段，不生成授信或资金。卡管理失败/取消不改变卡片，未知结果先查询，防止重复执行。
- 转账与卡管理记录进入原“任务与记录”，使用原确认、取消、失效、验证、回执及回放结构；不建立第二份记录。
- 浏览器本地保存快照，刷新可恢复；待确认记录可继续确认，但验证必须重做。授权最长24小时，可主动撤销；到期阻止操作并提示重新授权。关闭确认视为取消，刷新则保留尚未提交的确认任务。
- 保存失败显示明确警告；损坏快照保留原内容、阻止覆盖和写操作；旧标签页版本冲突阻止覆盖，提示刷新；可下载备份。
- “刷新保留”按钮及辅助文案统一；页脚、授权、回放说明改为准确的本地保存边界。
- 关键提交显示本地处理状态、禁用重复提交，随后根据真实本地规则结果显示成功/失败。本版本没有网络业务请求或同步 XHR；没有修改组长尚未提供的 server-bridge.js。
- 新卡管理适配桌面与窄屏；弹窗具备名称、错误提示、键盘焦点和 Escape 关闭，关闭后返回入口焦点；改善支持文字的对比度。

## 演示步骤

1. 授权中心勾选查询、转账、卡管理（原理财/订阅按需），保存。
2. 首页“打开模拟转账”，默认小王 800 元，生成确认；填写 246810 并确认。任务页显示完成；总览余额 38640 → 37840，总资产 128640 → 127840，支出12860 → 13660。
3. 刷新：上述变化保留。通过任务页查看回执；生成待确认任务后刷新，可从任务页继续确认。
4. 卡管理调低借记卡限额，再尝试超限转账，会被拦截。限制交易/挂失后，同一付款卡不能再转账。
5. 申请模拟借记卡：确认后为待审核；沙箱设置推进1天，再到任务页“查询开卡审核”选择模拟通过/拒绝。通过后新卡出现且可选为付款卡。
6. 沙箱设置可指定新操作模拟成功、失败、未知；未知不按成功改账，先查询原回执；不能直接重发。
7. 原订阅、产品比较、预演、申购与赎回入口保持。赎回受理不立即到账，推进1天后查询。

## 尚未完成与对接边界

- 未对接语嫣模拟卡 API、组长 SQLite 或接口契约。前端模拟已可独立交付；不能宣称 FirstAgent 集成修改完成。
- `local-store.js` 是当前数据持久化适配层；后续按正式契约对接服务端，以服务端为唯一权威状态。当前核心方法为同步调用，未来异步适配需一起调整调用方，不是简单替换网址。
- 本地数据可被浏览器修改，不是防篡改审计、正式身份验证或可靠后台调度。文件移动、浏览器切换、无痕模式和清除站点数据会影响恢复；不跨设备同步。
- 定时转账、AA、真实联系人验证、生日自动联动/商户下单、异常交易自动识别、完整年度报告、正式风险测评仍未实现，原卡片能力说明保留边界。
- 未添加或声称具备债务比率/流动性外部引用，因为当前未取得组长对应数据与来源。
- 本版本不提供一键清空记录；下载备份后可自行清除浏览器站点数据开始新的演示。

## 源码

`journey-engine.js`：确定性规则和共享状态；`local-store.js`：持久化/快照版本保护；`journey-workspace.js`：UI、表单和任务；`journey-workspace.css`：原视觉与新增面板样式。无运行时第三方网络依赖。
