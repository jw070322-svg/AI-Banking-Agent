## 4. 给不同队友的读取入口

### 4.1 推荐模块

读 `recommendation.profile.json`，结构对齐 `matching_core` 的 `user`：

| 字段 | 含义 | 单位/缺失处理 |
|---|---|---|
| `user_id` | 用户标识 | 字符串或 `null` |
| `risk_tolerance` | 风险承受意愿 | 缺失为 `null`，推荐模块应返回 `needs_profile_completion` |
| `risk_capacity` | 风险承受能力 | 缺失时默认 1，并在 assumptions 说明 |
| `budget_cny` | 可投金额 | **CNY 元**，不是整数分 |
| `horizon_days` | 投资期限 | 天；默认 30，或 goal.months × 30 |
| `max_redemption_days` | 最长赎回天数 | 默认 1 |
| `objective` | 目标 | 默认 `liquidity` |
| `preferred_categories` | 偏好类别 | 默认 `["cash"]` |

`conditions` 里同时给出整数分的可投上限、配置金额、分析上限、结余、最低余额、
缺口日和预算策略，便于追溯。可投金额规则：

```text
有配置金额且分析上限 > 0：min(配置金额, 分析上限)
无配置金额：分析上限
分析上限 = 0：保留配置金额，并提示先补应急金
```

### 4.2 卡管理 / 风控

读 `cards.view.json`：

- `cards`：卡 ID、类型、脱敏卡号、状态、限额（整数分）；
- `credit_card_bill`：账单日、还款日、应还/已还/未还（整数分）；
- `card_events`：提额、限额、冻结/解冻、挂失补卡等事件；
- `available` 与 `missing`：没有数据时明确标记，不编造卡状态。

当前这是**数据能力**；FirstAgent 的卡申请/挂失操作尚未接入，不能宣称已完成卡操作。

### 4.3 界面

- 实时会话：继续读 `/api/snapshot`，不要把 `display.view.json` 当账本；
- 生成场景演示：可读 `display.view.json`，它包含余额、当月收入/消费、订阅数、
  卡片数和 `read_only=true`、`ledger_modified=false`；
- `display` 不包含 consent、待确认操作和操作状态，不能替代实时快照。

### 4.4 知识模块

不消费客户流水。整理 Agent 不生成客户数据给 RAG；知识问答仍使用银行知识原文，
客户事实由主 Agent 在回答时引用分析结果。不要把 `package.json` 喂给 RAG。

### 4.5 集成负责人

- 分析工具：`POST/GET /api/analysis`，会话内 8 个只读工具；
- 推荐金额：`recommend` 响应新增 `budget_basis`，标注 `configured / engine / analysis`
  来源；
- 场景生成：`POST /api/scenarios/generate`，默认不返回 `expected_insights`；
- 数据整理：本期是纯函数 + CLI，尚未包装成 `data.organize` 工具，等队友确认
  消费方式后再接。

## 5. 数据契约

| 项目 | 规则 |
|---|---|
| 金额 | 一律 CNY 整数分；`recommendation.profile.budget_cny` 是唯一 CNY 元字段 |
| 状态 | 只统计 `status=booked`；`rejected/failed/pending` 不参与余额和消费 |
| 消费口径 | 借记卡 expense + 信用卡账单 expense，退款按负数冲减 |
| 转账 | `transfer_out` 不是消费，单独统计 |
| PII | 不含身份证、手机号、邮箱、住址、完整卡号；整理时再兜底扫描一次 |
| 标准答案 | `expected_insights` 默认剥离，评测时显式 `include_evaluation=true` |
| 只读 | 所有分析/整理结果 `simulated=true`、`ledger_modified=false` |

## 8. 已知边界与不能声明

1. **真实数据未校准**：类别阈值、订阅 3%/8% 分级、1/3 个月缓冲都是原型策略；
2. **同源评测不是真实准确率**：A~G 的 P/R/F1=1.0 只证明规则与生成数据一致；
3. **没有训练型模型**：当前是确定性规则 + 现金流推演 + 敏感性回测，没有 ML/外部模型；
4. **卡操作未接入**：G 场景有卡数据，FirstAgent 尚未实现卡申请/挂失操作；
5. **会话账本限制**：月度汇总样本，不能逐笔识别重复扣款；无信用卡账单、生日、日历；
6. **幂等是单机 SQLite**：不覆盖多实例/分布式；没有 TTL 清理；
7. **农历节日仅 2026–2027**：演示对照表，不是专业历法库；
8. **推荐不是投资建议**：是偏好排序；预算是确定性推演，不是收益预测。
