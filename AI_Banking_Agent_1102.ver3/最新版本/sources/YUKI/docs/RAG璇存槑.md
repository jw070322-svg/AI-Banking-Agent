# RAG 说明：最小可运行版本

## 1. 什么是 RAG
RAG（Retrieval-Augmented Generation）中文可理解为“检索增强生成”。它的核心思想是：在回答问题之前，先从外部知识库中检索与问题最相关的信息，然后再让模型基于这些信息生成回答。

与传统直接生成答案的方式不同，RAG 不是让模型“凭经验猜”，而是让模型“先查资料，再回答”。

## 2. 为什么 AI Banking Agent 需要 RAG
金融场景中的问题通常具有以下特点：
- 需要专业知识
- 需要业务规则
- 需要区分正常与异常
- 需要解释依据
- 需要保障安全边界

如果模型直接回答，容易出现以下问题：
- 过度泛化
- 依据不足
- 误导用户
- 在风险场景中不知如何拒答
- 无法说明结论来源

因此，AI Banking Agent 需要 RAG，把银行业务知识、合规边界、风险判断和典型案例组织成知识库，然后在回答时用于支撑结论。

## 3. RAG 在本项目中的作用
在本项目中，RAG的作用主要体现在以下几个方面：

### 3.1 提高回答可信度
当用户询问：
- 为什么储蓄率下降？
- 为什么转账未到账？
- 为什么会出现重复扣款？
AI 会先从知识库中查询相关规则与案例，再生成解释。

### 3.2 提供依据
与传统聊天机器人不同，本项目的回答不仅要有结论，还希望有“依据”，例如：
- 来自现金流说明
- 来自储蓄率说明
- 来自风险管理说明
- 来自合规边界说明

### 3.3 支持风险判断
当用户提出越权或危险问题时，AI 可以从合规知识中判断：
- 这是越权请求
- 这是敏感数据访问
- 这是需要拒答或转人工的情况

### 3.4 提高解释性
金融场景需要解释，而不是简单输出一个结论。RAG使得 AI 更容易说明：
- 结论来源于什么知识
- 哪些规则被用到
- 哪些情况需要进一步确认

## 4. 最小 RAG 架构
本项目的最小 RAG 结构可以概括为：

用户问题 → 检索知识库 → 返回相关文档片段 → AI 生成回答 → 附带依据和风险判断

核心流程如下：
1. 用户提问
2. 程序根据关键词检索知识库
3. 匹配相关 Markdown 文档
4. 提取最相关片段
5. 把片段作为上下文输入给模型
6. AI 基于这些信息生成回答
7. 若问题涉及风险或越权，则触发拒答逻辑

## 5. 知识库来源
本项目的知识库来自：
- 银行业务知识说明
- 典型金融场景
- 典型案例
- 风险与合规规则
- 任务说明和业务边界

这些内容全部存放在 data/knowledge/ 文件夹中。

## 6. 本项目的最小实现思路
最小实现方式可以非常简单，不需要复杂的向量数据库。建议先采用以下方式：

- 读取 data/knowledge 中的 Markdown 文件
- 读取用户问题
- 提取关键词
- 通过文本匹配或简单相似度计算找出最相关文档
- 把相关文档内容拼接到提示词中
- 模型根据这些上下文生成回答

这种做法非常适合比赛初期，因为：
- 实现简单
- 容易理解
- 容易测试
- 容易展示

## 7. 安全边界
RAG 只是知识增强，不等于权限提升。

也就是说：
- 它不能让 AI 直接访问真实客户信息
- 它不能绕过权限控制
- 它不能把敏感数据直接当作回答内容
- 它不能在越权场景中直接执行动作

在本项目中，RAG 仅用于：
- 金融知识回答
- 常见场景解释
- 风险判断
- 合规边界提醒

## 8. 结论
RAG 是 AI Banking Agent 可信性、解释性和安全性的关键基础之一。它让 AI 不再只是“直接编造答案”，而是通过检索知识库来回答问题。

对于本项目而言，最重要的不是把 RAG 做得很复杂，而是先让它真正能够：
- 查到相关知识
- 形成有依据的回答
- 在高风险场景中拒答或转人工

这也是本项目最关键的价值体现之一。
