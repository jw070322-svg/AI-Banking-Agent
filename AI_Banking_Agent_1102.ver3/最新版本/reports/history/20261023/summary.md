# SecondAsgent 总版总结（2026-10-23）

## 版本比对与选择依据

递归盘点 105 个非缓存输入文件；较首轮增加 28 个文件，原 77 个输入哈希未变。覆盖 eva output、vv output、YUKI ouput（原目录拼写）及 Ethan output 内的嵌套 output。

最新单页时间较晚；逐脚本比较发现 ZIP 含 trade 映射、预览/断言期限、累计分级等补丁。以单页新增业务功能为目标，从完整 ZIP 源码补齐契约保护，并连接服务端。

eva 沿用 1020/ver.2；YUKI 沿用 1022；vv 纳入 1023 单页及源码；Ethan 纳入 1022 环境生成和各家族 20261022185343 最新 A–E 样例。来源、时间、哈希见 reports/source_inventory_20261023.json、update_metadata.json。

## 架构、接口与集成

vv 页面 → BankCore HTTP 适配 → Python AgentService → SQLite 单一事务状态 → 服务端 Node 引擎 / eva 风控 / 推荐 / RAG；Ethan 独立场景生成不修改账本。

卡片申请、限额、限制、解锁、挂失及选择付款卡已接入；两条转账入口共用资金、卡限制、风险累计、操作记录和审计。

接口详情见 [API-CONTRACT.md](API-CONTRACT.md)。金额统一为分；授权 24 小时；预览 300 秒；增强验证断言 120 秒。模拟卡额度不是新增资金。真实银行由组委会接入。

## 缺失补丁及反思

- 不能仅凭文件修改时间推断语义版本：本轮同时记录单页和 ZIP 的时间、哈希及脚本差异，用完整源码中的契约补丁补齐单页缺项。

- 浏览器刷新时清除验证与可信服务端每请求恢复不是同一场景：仅服务端恢复保留 verified，仍以服务端断言绑定与真实时钟判断期限。

- 卡管理不是独立资金池：新旧转账入口统一累计和卡支出，externalOut 记录对外转出，开卡/额度变更不产生存款。

- 有 validator 文件不代表验证完整：结构校验之外显式复用 fallback 场景校验并增加整数分精确对账。

- 分工归属以交付内容核实：Ethan 已明确为环境生成；推荐补丁的来源与集成维护责任单独记录。

- 测试数量须按独立用例统计：本轮为 32 项集成与 35 项 JS，清除了导入旧测试类带来的重复计数。

## 遗留问题

- 目前仅本地规则驱动模拟 Agent；没有真实银行连接、真实验证码或开放式大模型。真实银行由组委会部署接入，不属于团队欠交项。

- 同步 XHR 兼容层仍在，较慢请求会阻塞页面；尚未完成全面异步改造及全尺寸无障碍验收。

- 旧聊天名册与新页面联系人集合不同，但均使用共同账本、限额和卡状态。

- 历史旧转账记录可能没有创建时快照，公开投影使用空历史字段；不会伪造历史资金数据。

- 场景只生成独立数据，不自动导入用户会话；未支持所有任意自然语言需求或真实客户数据。

- 原 eva 缺依赖和 YUKI 全量 50 题评测仍待分支补交；本地 SQLite 审计不提供生产防篡改保证。

## 额度、交付与复跑

只监测 300 分钟窗口；周额度完全不参与停止判断。小于 10% 才中止，等于 10% 仍未触发。采样见 reports/quota_latest.json 与 quota_history.json；监测依赖当前任务调用账户工具，不是脱离任务独立运行的后台进程。
